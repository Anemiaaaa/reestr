# Реестр задач

Инструмент проект-менеджера: сгружаете в задачу переписку, ТЗ и аудит — получаете
**срез по задаче** (что происходит, где встало, чего не хватает, что делать) и
**схемы процесса «как есть» / «как будет»**.

Каждая строка среза помечена тем, откуда она взялась: процитировано из источника,
выведено из него, посчитано кодом или не найдено вовсе. Пробелы не замазываются —
они показываются как пробелы.

Сервис запускается одной командой, без базы и без сборки фронтенда.

---

## Быстрый старт

```bash
go run ./cmd/reestr
```

Откройте <http://127.0.0.1:8080>. Пустое хранилище при первом запуске заполняется
разбором реальной задачи — можно сразу щупать.

Нужен Go 1.22 или новее. Сторонних зависимостей нет: только стандартная
библиотека.

### Флаги

| Флаг | По умолчанию | Зачем |
|---|---|---|
| `-addr` | `127.0.0.1:8080` | Адрес. Только петля, а не все интерфейсы: в файле лежит аудит заказчика с оборотами и сметой. |
| `-data` | `data/reestr.json` | Файл с данными. Всё состояние в нём, открывается текстовым редактором. |
| `-web` | *(пусто)* | Каталог с интерфейсом вместо вшитого в бинарник. Правку в CSS видно после F5, без пересборки. |
| `-seed` | `true` | Заполнить **пустое** хранилище демонстрационным разбором. Существующие данные не трогает. |
| `-v` | `false` | Подробный лог. |

## Что это решает

PM ведёт задачу в трекере, а правда о ней размазана по переписке, аудиту и
вложениям. Карточка говорит «в работе», хотя решения по подходу нет два месяца.
Срок переносили трижды, причина не записана ни разу. План есть, но никто не
считал, сколько из него закрыто.

Инструмент собирает из этих источников одну страницу, на которой:

- видно **этап и готовность** — и готовность посчитана, а не вписана на глаз;
- видно **блокер и его возраст в днях**;
- видно **чего не хватает**, чтобы двинуться дальше;
- у **каждого утверждения** есть цитата или объяснение, откуда оно.

## Как это работает

```
   источники              факты                    срез
 ┌─────────────┐      ┌─────────────┐      ┌──────────────────┐
 │ переписка   │      │ атомарные   │      │ 6 разделов       │
 │ ТЗ          │ ──▶  │ утверждения │ ──▶  │ + схемы AS IS /  │
 │ аудит       │      │ с цитатой и │      │   TO BE          │
 │ пояснения   │      │ ссылкой на  │      │ + все числа      │
 └─────────────┘      │ источник    │      │   посчитаны      │
                      └─────────────┘      └──────────────────┘
   только              только                пересобирается,
   добавляются         добавляются           не правится
```

1. **Источник** — кусок текста как есть: переписка, ТЗ, аудит, заметка. Не
   редактируется и не удаляется.
2. **Аналитик** читает источники и выдаёт **факты**: «поле такое-то равно такому-то,
   вот цитата, вот ссылка на источник, вот насколько я уверен». Факт — атомарное
   утверждение, а не абзац.
3. **Сервис** раскладывает факты по полям среза и **считает всё остальное**:
   готовность, просрочки, возраст блокера, количество пробелов.
4. **Срез** — проекция. Его не правят: добавляют источники и пересобирают, версия
   растёт, прежние версии остаются лежать.

### Разделение труда: модель извлекает, код считает

Ключевое правило. Аналитик (позже — ИИ) **только извлекает** факты с цитатами.
Вся арифметика — в Go.

Почему так: «27 % готовности» должно получаться из одних и тех же источников
одинаково при каждом запуске, и любую цифру должно быть можно проверить руками.
Модель этого не гарантирует, код гарантирует. Поэтому модель никогда не
складывает и не делит — она находит и цитирует.

### Правила, на которых всё держится

| Правило | Почему |
|---|---|
| Источники и факты **только добавляются** | История разбора не переписывается. В `store` намеренно нет методов `Update` и `Delete`. |
| Срез **пересобирается**, а не правится | Правка среза оторвала бы его от источников, и он перестал бы быть проверяемым. |
| Модель извлекает — **код считает** | Воспроизводимость чисел. |
| Фронтенд **не считает ничего** | Пока фронтенд считает сам, он рано или поздно посчитает иначе, чем бэкенд, и на экране окажутся два разных процента готовности из одних данных. API отдаёт числа уже посчитанными и подписи уже подставленными. |
| Отсутствие данных — **значение**, а не пустая строка | «Дата постановки не названа в переписке» — это факт о задаче, и он должен быть виден. |
| Чужой текст выводится **только через `textContent`** | Переписка и аудит — чужой текст, разметкой он быть не должен. `innerHTML` не используется нигде. |

## Что такое срез

Семь разделов. Шесть пронумерованы — это шаблон, по которому PM читает задачу;
седьмой служебный.

| № | Раздел | Что внутри |
|---|---|---|
| 1 | **Паспорт задачи** | Название, автор постановки, исполнитель, дата постановки, срок, бюджет. Плюс список переносов срока — с пометкой, объяснён перенос или нет. |
| 2 | **Цель и границы** | Зачем задача, критерии приёмки (галочками), что вынесено за рамки. |
| 3 | **Статус и план** | Этап, готовность, этапы плана с датами и просрочками. |
| 4 | **Блокеры и риски** | Блокеры с возрастом в днях, риски с последствием. |
| 5 | **Что делать PM** | Ближайшие действия, следующая точка контроля. |
| 6 | **Вопросы специалисту** | Что нужно спросить, чтобы двинуться; у каждого вопроса — что он разблокирует. |
| — | **Артефакты** | Какие документы на руках, каких нет и что дал бы каждый отсутствующий. |

### Откуда взялась каждая строка

У каждого значения в срезе есть знак происхождения. Он кликабельный: под ним
цитата или объяснение и ссылка на источник.

| Знак | `origin` | Значение |
|---|---|---|
| `↩` | `quoted` | Процитировано из источника. Есть цитата. |
| `→` | `derived` | Выведено из источника. Есть объяснение, почему так. |
| `∑` | `computed` | Посчитано кодом из фактов. Есть расшифровка счёта. |
| `?` | `missing` | Данных нет. Есть объяснение, чего именно не хватает. |

### Пример: факт из переписки перебивает карточку

В карточке задачи постановщик — Ризван Мирзаев. Но требования, оценку плана и
приёмку по переписке ведёт другой человек. Срез показывает второго и объясняет
почему:

```json
{
  "text": "Курбанмагомед Джамалутдинов",
  "origin": "derived",
  "originLabel": "выведено",
  "mark": "→",
  "sourceId": "aura-history",
  "sourceTitle": "История задачи «Внедрение Автоматизация Бизнес процессов АУРА»",
  "note": "в карточке постановщик — Ризван Мирзаев, но требования, оценку плана и приёмку ведёт Курбанмагомед"
}
```

Для сравнения — название задачи, взятое из карточки как есть:

```json
{ "text": "Внедрение Автоматизация Бизнес процессов АУРА",
  "origin": "quoted", "mark": "↩", "note": "поле карточки задачи" }
```

Правило: карточка — не источник. Она говорит, что в неё вписали, а не что
происходит. Факт из переписки перекрывает поле карточки, но обязан объяснить, на
каком основании.

### Схемы процесса

Аналитик выдаёт процесс дорожками: шаг, чья дорожка, позиция в потоке, есть ли
проблема. Сервер считает раскладку по сетке (строка — участник, столбец — позиция),
считает статистику и отдаёт готовое; браузер только расставляет по `grid`.

Схема «как есть» помечает проблемные шаги и возвраты назад. Схема «как будет»
показывает, что меняется, списком изменений с пометкой операции.

## API

Всё под `/api`, ответы — JSON с отступами (его читают руками через `curl`).

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/health` | Живость, имя аналитика, время сервера. |
| `GET` | `/api/tasks` | Список задач с посчитанным сроком и признаком просрочки. |
| `POST` | `/api/tasks` | Создать задачу. |
| `GET` | `/api/tasks/{id}` | Одна задача. |
| `GET` | `/api/tasks/{id}/board` | **Всё для страницы одним ответом**: задача, срез, схемы, источники, число фактов. |
| `GET` | `/api/tasks/{id}/slice` | Последний срез. Если среза нет — соберёт. |
| `POST` | `/api/tasks/{id}/slice/rebuild` | Пересобрать срез заново. Версия +1. |
| `GET` | `/api/tasks/{id}/sources` | Источники без тел. |
| `POST` | `/api/tasks/{id}/sources` | Добавить источник. |
| `GET` | `/api/tasks/{id}/processes` | Схемы «как есть» / «как будет». |
| `GET` | `/api/tasks/{id}/facts` | Журнал фактов: что аналитик утверждал и с какой уверенностью. |
| `GET` | `/api/sources/{id}` | Источник с полным текстом. |

`board` — отдельный маршрут, а не четыре запроса из браузера: срез читают целиком,
и части его должны быть из одной сборки. Иначе на экране окажется готовность из
версии 3 рядом со схемой из версии 2.

```bash
curl -s http://127.0.0.1:8080/api/health
# {"analyst":"ручной разбор","now":"2026-08-21T13:04:39Z","ok":true}

curl -s http://127.0.0.1:8080/api/tasks/aura/slice | head -40
```

Коды ошибок: `400` — некорректные данные, `404` — не найдено, `409` — уже
существует, `500` — остальное. Текст ошибки уходит клиенту как есть: инструмент
локальный, читает его тот же человек, что запустил сервер.

## Архитектура

Зависимости направлены внутрь: `domain` не знает ни про HTTP, ни про хранилище, ни
про аналитика.

```
cmd/reestr  ──▶  httpapi  ──▶  service  ──▶  domain
                                  │  ├──▶  store  ──▶  jsonstore
                                  │  └──▶  analyst ──▶  manual
                                  └──▶  ru
web (embed) ──▶  httpapi
```

| Пакет | Отвечает за | Зависит от |
|---|---|---|
| `internal/domain` | Сущности и правила: задача, источник, факт, срез, процесс. Значение с происхождением. | только stdlib |
| `internal/ru` | Русские числа, проценты, склонения: «74 дня», «8 этапов», «27 %». | stdlib |
| `internal/store` | Интерфейс хранилища. Без `Update` и `Delete` — намеренно. | `domain` |
| `internal/store/jsonstore` | Хранилище в одном JSON-файле. Запись атомарная: временный файл и переименование. | `domain`, `store` |
| `internal/analyst` | **Интерфейс аналитика — шов для ИИ.** | `domain` |
| `internal/analyst/manual` | Разбор задачи АУРА, сделанный руками, и демонстрационные данные. | `domain`, `analyst` |
| `internal/service` | Сборка среза и вся арифметика. | `domain`, `store`, `analyst`, `ru` |
| `internal/httpapi` | Маршруты и представление: числа посчитаны, подписи подставлены. | `service`, `domain`, `ru`, `store` |
| `web` | Интерфейс, вшитый в бинарник через `embed`. Без сборки, без зависимостей. | `io/fs` |
| `cmd/reestr` | Флаги, запуск, посев, корректная остановка. | всё выше |

Сборка среза чистая: `assemble` принимает всё параметрами — источники, факты,
вывод аналитика, время, — и не трогает ни хранилище, ни часы. Часы сервиса
подменяются через `Service.Clock`, поэтому тесты на даты стоят на фиксированном
дне.

### Модель данных

| Сущность | Ключевые поля |
|---|---|
| `Task` | проект, название, автор, исполнитель, дата постановки, срок, бюджет |
| `Source` | вид (переписка / ТЗ / аудит / заметка), заголовок, текст, когда загружен |
| `Fact` | поле среза, значение, ссылка на источник, цитата, уверенность, когда наблюдалось |
| `Value` | текст, происхождение (`quoted` / `derived` / `computed` / `missing`), цитата, ссылка, пояснение |
| `Process` | вид (`as_is` / `to_be`), дорожки, шаги, связи, изменения |
| `Slice` | номер версии, дата сборки, все разделы, ссылки на источники, кто разбирал |

## Куда подключается ИИ

Шов уже есть. Аналитик — интерфейс:

```go
type Analyst interface {
    Name() string
    Extract(ctx context.Context, in Input) (Output, error)
}
```

`Input` — задача, её источники и дата, на которую собирается срез. Дата
передаётся параметром, а не берётся из часов: тот же вход должен давать тот же
выход.

`Output` — факты, этапы плана, переносы срока, блокеры, риски, вопросы,
артефакты, критерии приёмки, схемы процессов, цель и границы. Ни готовности, ни
просрочек, ни числа пробелов в нём нет: это производные величины, их считает
сервис.

Сейчас интерфейс реализует `analyst/manual` — разбор, сделанный руками.
Подключение модели — это **новый пакет рядом**, например `analyst/claude`, который
реализует тот же интерфейс. Ни домен, ни сервис, ни API, ни фронтенд при этом не
меняются: в `cmd/reestr` подставляется другая реализация.

Что обязана делать реализация на модели:

- вернуть на каждый факт **цитату и ссылку на источник** — без них факт не
  принимается;
- **не считать**: проценты, дни и количества посчитает сервис;
- ставить **«нет данных»** там, где в источниках ответа нет, вместо догадки.

Что для этого понадобится (пока не сделано): запрос к модели со структурированным
выводом по схеме `Output`, проверка, что цитаты действительно встречаются в тексте
источника, и кэш разбора, чтобы пересборка не платила за модель дважды.

## Демонстрационные данные

При первом запуске в пустое хранилище кладётся реальная задача: внедрение
автоматизации у дистрибьютора бытовой химии. Два источника — история задачи из
трекера и документ аудита.

Что из них собирается:

| | |
|---|---|
| Источников | 2 |
| Фактов | 32 |
| Этапов плана | 9, из них 8 просрочено |
| Готовность | **27 %** (2,4 из 9 этапов) |
| Блокеров | 1, с 8 июня 2026 — возраст в днях считается от текущей даты |
| Рисков | 7 |
| Вопросов специалисту | 13 |
| Критериев приёмки | 6, выполнено 0 |
| Артефактов | 4 |
| Пробелов | 8 |
| Схем | 2 (как есть, как будет) |

Разбор сделан руками — это и демонстрационные данные, и образец того, что должна
выдавать модель.

## Что готово и что нет

Готово:

- домен, хранилище, сервис, API, интерфейс — работают;
- срез собирается из источников, все числа считаются кодом;
- схемы «как есть» / «как будет» рисуются;
- журнал фактов виден отдельной вкладкой;
- добавление источника и пересборка среза — из интерфейса;
- тесты на домен, хранилище и сервис проходят.

Не готово:

- **разбор источников моделью** — сейчас работает `analyst/manual`, разбор одной
  задачи, сделанный руками. Новые источники в срез не попадут, пока не появится
  `analyst/claude`;
- хранилище — JSON-файл: данные можно открыть редактором, но нагрузку он не
  держит. Когда файла станет мало, рядом появится `store/sqlite`; сервис знает
  только интерфейс и разницы не заметит;
- аутентификации нет. Инструмент локальный, слушает петлю.

## Разработка

```bash
gofmt -l .        # форматирование
go vet ./...      # статические проверки
go test ./...     # тесты
go build ./...    # сборка
```

Интерфейс без пересборки — отдавать из каталога:

```bash
go run ./cmd/reestr -web web
```

Начать с чистых данных:

```bash
go run ./cmd/reestr -data /tmp/reestr/reestr.json
```

Комментарии в коде на русском, имена — английские.
